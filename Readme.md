# new_nav

> 哨兵导航代码

## 包含的包

- **algo_master** —— 下位机通信
- **controller** —— 无用，暂未实现
- **custom_msgs** —— 自定义消息包
- **esdf** —— 点云转导航地图（占据栅格与 ESDF）
- **livox_ros_driver2** —— MID360 ROS2 驱动
- **planner** —— 规划器
- **point_lio** —— 开源里程计
- **relocation** —— 定位与重定位

> 暂时没写决策相关

## 架构说明

包与包之间高度解耦合，只通过 ROS 的话题进行通信，可以分开跑。只要满足相应的话题名称与消息类型即可。

`esdf`、`relocation`、`planner` 包均带有非 ROS 的 test 文件，**请务必在使用之前运行 test 文件**，具体原因见各个包的说明。

`point_lio` 和 Livox 相关内容不再赘述，请自行查阅相应的开源文档或官方文档。

## 注意事项

- 由于下位机云台坐标系每次上电不一致，采用**相对云台坐标系**进行。
- 由于里程计与初始位姿不同，此处将所有坐标系转化为 **MAP 坐标系**，即占据栅格的坐标系。

## 相关环境与依赖

可能需要的环境：`opencv`、`ros2`（很多包）、`spdlog`、`json`……可以阅读 `CMakeLists.txt` 和 `package.xml` 文件确认。

运行 test 和 node 之前**记得检查路径**，部分使用了绝对路径（因为相对路径不知为何读不出来）。

> 很多代码都是从头造的轮子，因为开源方案多是 3D 导航，不适配 2D 场景，且计算开销和代码复杂度较高（悲）
